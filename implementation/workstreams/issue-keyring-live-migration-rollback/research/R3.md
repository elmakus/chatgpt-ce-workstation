## Scope

Evidence-first diagnosis only until the mechanism is proven.

Do not:
- rerun/promote another live production candidate under the completed authorization;
- delete/reset live keyring collections/items;
- clear or replace the retained live migration credential;
- expose secret values;
- weaken strict candidate verification or D26;
- absorb issue #11 or unrelated workstation changes.

Read-only production metadata and disposable isolated tests are permitted where they do not expose keyring secret values or mutate live persistent keyring state.

## Known evidence

- Exact reviewed subject `789fc358...` passed hosted CI and Tower source validation.
- Its per-session readiness marker is cleared before desktop substrate startup and published only after `keyring-passwordless.py` returns success.
- The promoted candidate reached Docker `healthy`.
- Strict verification immediately afterward still failed because the canonical login collection was locked.
- Rollback restored/verified the exact prior image with `ROLLBACK_RUNTIME_GREEN`.
- Post-rollback markers are absent and the retained migration credential remains available.
- Additional empty keyring-file creation across live restart windows indicates session/file lifecycle behavior not represented by the current readiness regression.

## Questions

1. Does the helper's successful unlocked check survive helper process exit on the same canonical D-Bus/Secret Service daemon, or does the collection relock asynchronously?
2. Is the helper and strict verifier actually querying the same Secret Service daemon/collection object after startup?
3. Does `ChangeWithMasterPassword` on the production-derived legacy collection persist empty-master-password state to the intended backing file before the helper reports success?
4. Does daemon/session restart or natural-login collection reload select a different on-disk collection after migration?
5. What deterministic regression can reproduce the live transition from helper success/readiness to later locked verification?

## Exit criteria

Research is complete when evidence identifies the exact lifecycle failure mechanism and supports one bounded correction under current MF-T01/D26/R11-R12 authority, with a deterministic regression that fails before the correction and passes after it. If evidence instead requires changing accepted D26 intent, return for Project Definition rather than implementation.
