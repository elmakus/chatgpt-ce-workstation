## Scope

Establish source/runtime evidence only. Do not mutate the live persistent keyring, clear/replace the legacy migration credential, promote the failed candidate, rerun the normal updater, or change accepted D8/D14/D26 intent.

## Known evidence

- Real candidate `sha256:1e552c66...` failed runtime verification because the default Secret Service collection was locked.
- Exact previous image `sha256:ea264b43...` was restored, running and healthy.
- Rollback verification then failed on a post-D26 non-desktop D-Bus invariant absent from that older image.
- Candidate-era marker survived while migration backup was absent.
- Legacy migration secret remained non-empty.
- Operator removed only the stale marker; production remains on the previous known-working image.

## Questions

1. Can an encrypted login collection be already unlocked when `keyring-passwordless.py` starts, causing the helper to skip `ChangeWithMasterPassword` and incorrectly write its marker?
2. What observable operation safely proves that the persistent collection is passwordless across daemon/session restart without deleting items?
3. Does the real keyring contain alias/state/layout details not represented by the synthetic fixture?
4. What rollback verifier contract can validate exact restoration of an older retained image without applying candidate-only invariants, while keeping strict candidate verification unchanged?
5. What rollback state cleanup must occur even when no migration backup directory was created?

## Evidence method

Prefer a disposable copy of the real Tower keyring and non-secret metadata/runtime behavior. Never dump stored secret values. Reproduce under an isolated HOME/D-Bus session. Compare source behavior with the exact old/new verifier contracts and updater rollback state machine.

## Exit criteria

Research is complete when the evidence is sufficient to define one bounded fix Card covering:
- migration predicate/operation and marker semantics;
- backup/rollback-state semantics;
- version-aware rollback verification;
- deterministic regression tests reproducing both production failures;
- a later explicit live retry gate.

If findings require changing D26 or broader updater product policy, do not return to Execution Prep; record the blocker instead.
