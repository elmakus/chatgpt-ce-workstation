## Blocking finding

### R1 — keyring rollback restore is not fail-closed when a critical filesystem/container operation fails

MF-T01 Acceptance 6 requires the exact pre-attempt keyring directory to be restored before the previous image is recreated, and smart-updater R11 requires rollback failure to fail loudly rather than continue as if recovery succeeded.

On the reviewed subject, `rollback_after_failure` calls:

```bash
if ! restore_keyring_migration_backup; then
  ...
fi
```

Inside `restore_keyring_migration_backup`, the critical operations are not all checked explicitly:

```bash
rm -f "$marker" "$marker_v1"
[[ -d "$backup" ]] || return 0

docker compose stop workstation >/dev/null 2>&1 || true
rm -rf "$keyrings"
mv "$backup" "$keyrings"
```

Because the function is executed as the condition of `if ! ...`, Bash does not provide the expected `set -e` fail-fast behavior for commands inside that function. A failed marker removal may therefore be followed by a successful return when no backup exists. More importantly, a failed `docker compose stop` is explicitly ignored, and a failed active-keyring removal can be followed by `mv` against a still-existing destination.

That means a rollback attempt can continue mutating the persistent keyring while the candidate container may still be active, or can fail to restore the exact pre-attempt directory without reliably returning failure at the point required by `rollback_after_failure`.

This violates:
- MF-T01 Acceptance 6;
- MF-T01 Must preserve every existing keyring collection/item;
- D26 in-place migration/preservation;
- R11 deterministic, loudly failing rollback.

## Required correction

Within existing MF-T01 authority:

1. make every safety-critical restore step explicitly fail-closed rather than relying on `set -e` through a conditional function call;
2. do not replace the persistent active keyring unless the candidate workstation is confirmed stopped/absent;
3. if marker cleanup, stop/readback, active-keyring removal, or backup publication into the active path cannot be completed safely, return non-zero so `rollback_after_failure` records `keyring_restore_failed` and does not recreate the retained image as though the keyring restore succeeded;
4. add deterministic regression coverage for at least stop failure and filesystem restore failure, proving the pre-attempt backup is not consumed/misplaced and rollback does not report success.
