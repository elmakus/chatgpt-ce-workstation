## Outcome

The workstation source accurately documents the current Muse capability/skill ownership and persistent-home substrate, and validation guards prevent future workstation changes from silently isolating Muse from its persistent user state or moving rare administration into workstation-global policy.

## Scope

### Included

- Reconcile `docs/MUSE_CODE_PLAN.md` with D21/D25/D26 and the accepted structured-hint/admin architecture.
- Document Muse-owned MCP/auth and shared-skill state as native user/project state backed by the existing persistent home.
- Document structured hints as an external `codex_workflow` contract and administration as the dedicated `muse-capability-admin` skill.
- Add source validation for the persistent Muse home/ownership contract.
- Add read-only runtime verification that Muse executes with `HOME=/home/codex`.

### Excluded

- Any `codex_workflow` or `muse-capability-admin` source change.
- M02 structured-hint deployment verification and M03 live capability administration/E2E.
- New Compose mounts, secret backends or credential wiring unless later evidence proves a workstation-owned gap.
- Changes to global `defaults/AGENTS.md` beyond preserving its current absence of the full Muse administration runbook.
- Live Muse settings, OAuth grants, skill directories or external-service state.

## Acceptance

- Muse documentation is consistent with D21/D25/D26 and no longer describes workstation-owned worker lifecycle semantics.
- Muse user MCP/auth state and reusable user skills are documented as native Muse state under the existing persistent home, with trusted project scope kept distinct.
- The docs identify `codex_workflow` as structured-hint owner and `muse-capability-admin` as administration owner.
- Missing capability, mutation authority and credential availability remain explicitly separate.
- Source validation fails if the workstation stops providing `HOME=/home/codex`, the Muse wrapper overrides that home, or the capability-boundary documentation disappears.
- Runtime verification includes a read-only assertion that the Muse process environment uses `HOME=/home/codex`.
- No live Muse capability/auth/user-skill state is changed by M01.
