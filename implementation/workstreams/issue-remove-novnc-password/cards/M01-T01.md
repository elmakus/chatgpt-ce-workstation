### Must preserve

- Raw x11vnc/VNC remains bound only to container loopback and TCP 5900 is not host-published.
- Only websockify/noVNC remains published for the recovery desktop.
- The noVNC/VNC layer is intentionally passwordless; do not add replacement authentication, SSO, VPN, proxy auth, or another credential mechanism.
- Published noVNC remains intended only for trusted-network reachability unless a separately authenticated ingress is deliberately authorized later.
- Docker Compose remains runtime/deployment source of truth and the change must be reproducible from repository source.
- Existing obsolete `novnc-password` and `vnc.pass` files may remain on disk but current runtime must not depend on them.
- Preserve unrelated Docker isolation, mounts, privileges, GNOME Keyring, CE, Remote Control, Codex Web GPT and desktop supervision/relaunch semantics.
- Preserve rollback viability: do not destructively delete legacy VNC password artifacts as part of this source change.
- Live production deployment to the user's Unraid workstation is a separate explicit authorization gate.

### Must not / rationale that must travel

- Do not broaden `${NOVNC_BIND_IP}`, publish raw 5900, add `privileged`, add `SYS_ADMIN`, or otherwise weaken the container/network boundary to compensate for removing VNC authentication.
- Do not touch keyring authentication/migration behavior except where a shared validation message/check must be narrowly reconciled without changing its semantics.
- Do not perform destructive cleanup of legacy password files; they are useful for rollback to an older image.

## Dependencies

- none

## Outcome

The workstation source starts and exposes the recovery desktop through noVNC without requiring a VNC/noVNC password, while preserving the approved network and container isolation boundaries.

## Scope

### Included

- Remove `novnc_password` Compose secret wiring.
- Remove container-init generation/requirement of persistent `vnc.pass`.
- Configure x11vnc explicitly for passwordless access while retaining current loopback, display, port, lifetime and supervision behavior.
- Remove noVNC password prompting/requirement from host initialization and preflight.
- Reconcile source/runtime validation so passwordless behavior is required and legacy auth regressions fail.
- Update affected user/deployment documentation, including current password-secret and `vnc.pass` references.
- Add/preserve deterministic checks for no raw-VNC publication, loopback-only x11vnc and absence of required password artifacts.

Expected affected source surface includes:
- `compose.yaml`
- `rootfs/etc/cont-init.d/10-workstation-init`
- `scripts/container/desktop-session-inner.sh`
- `scripts/init-unraid.sh`
- `scripts/preflight-host.sh`
- `scripts/validate-source.sh`
- `scripts/verify-runtime.sh`
- `README.md`
- `docs/IMPLEMENTATION_PLAN.md`

Execution may adjust this exact list if current source inspection finds another direct password-auth dependency inside the same accepted scope.

### Excluded

- Live deployment/recreation of the user's production Unraid workstation without explicit authorization.
- New authenticated ingress, reverse proxy, VPN, SSO or replacement remote-desktop stack.
- Changes to GNOME Keyring target behavior, CE authentication, Android Remote Control authentication or Codex Web GPT authentication.
- Unrelated workstation cleanup/refactoring.

## Acceptance

- No current source/runtime path requires `APPDATA_ROOT/secrets/novnc-password`.
- No current source/runtime path requires or generates `/home/codex/.config/workstation/vnc.pass`.
- x11vnc is explicitly passwordless and still includes loopback-only binding.
- Compose publishes no raw VNC port and publishes only the existing noVNC/websockify endpoint.
- Fresh host initialization does not prompt for or create a noVNC/VNC password secret.
- Host preflight, source validation and runtime verification no longer require the legacy VNC secret/auth file.
- Deterministic validation rejects reintroduction of `-rfbauth`, required `novnc_password` wiring, or loss of loopback-only VNC.
- README/deployment documentation no longer instructs users that a noVNC password/secret is required and states the trusted-network consequence of passwordless access.
- Existing keyring/application/container-isolation validation remains intact.
- Build/runtime smoke or materially equivalent exact runtime evidence proves the desktop/noVNC stack can become healthy with no `novnc-password` secret.

## Required tests / checks

- `bash -n` / existing shell syntax coverage for edited shell files.
- `bash scripts/validate-source.sh`.
- Compose/static inspection proving no `novnc_password` secret and no host publication of TCP 5900.
- Deterministic inspection proving x11vnc remains `-localhost` and no longer uses `-rfbauth` or a VNC auth file.
- Runtime verification updated to treat `vnc.pass` as absent/irrelevant while retaining isolation/keyring/application checks.
- Image build or equivalent build validation.
- Exact non-production container/runtime smoke with the noVNC secret absent, when a permitted runtime surface is available; otherwise persist the concrete runtime blocker rather than substituting a live production write.
- Regression check of noVNC desktop health/supervision and preserved unrelated keyring/application/isolation assertions.
