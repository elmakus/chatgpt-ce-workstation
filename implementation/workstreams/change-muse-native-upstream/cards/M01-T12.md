### Must preserve

- One normal user-facing `scripts/update.sh` operation.
- One immutable frozen upstream resolution per D25 attempt.
- Exact Ubuntu InRelease SHA-256 validation remains fail-closed; no alternate hash set, wildcard, stale acceptance, bypass or soft warning is allowed.
- A retry must rebuild against the **same frozen resolution**. It must not silently re-resolve upstreams between build attempts.
- Retry eligibility is narrow: only a candidate-build failure whose build output contains the exact Ubuntu InRelease identity-mismatch diagnostic from `assert-ubuntu-apt-identity.sh`.
- Any unrelated candidate-build failure remains immediately terminal.
- Retry count is bounded; exhaustion remains `pre_promotion_failed / candidate_build_failed`.
- No production recreation/promotion may happen before a candidate build succeeds and all normal D25 readback gates pass.
- Expert pins/overrides remain explicit recovery/debug controls and are not introduced by this fix.
- M01-T11 exact Codex Web GPT v5.0.15 provenance is not changed by this Card.

- `M01-T10`

## Outcome

D25 can survive a short `archive.ubuntu.com` mirror-propagation window by retrying the exact frozen candidate build a small bounded number of times, while preserving exact APT identity validation and all existing fail-closed semantics.

## Scope

### Included

- Refactor the physical candidate build into a single-attempt helper if needed.
- Add a bounded wrapper in `scripts/update.sh` that:
  - attempts the exact same frozen candidate at most three times;
  - retries only after detecting `Ubuntu InRelease SHA-256 mismatch for ` in that attempt's build output;
  - emits a concise retry diagnostic;
  - does not call the resolver again;
  - returns failure after the third retryable mismatch;
  - returns immediately on any non-mismatch build failure.
- Extend deterministic updater orchestration tests for:
  - ordinary generic build failure => one attempt, terminal;
  - transient APT mismatch followed by success => bounded retries then normal success path;
  - repeated APT mismatch through the retry limit => terminal pre-promotion failure with zero production recreate.
- Keep existing updater orchestration scenarios GREEN.

### Excluded

- Changing Ubuntu repository/channel/mirror policy.
- Pinning a mirror IP, using an Ubuntu snapshot service, or persisting alternate accepted hashes.
- Weakening/removing `assert-ubuntu-apt-identity.sh`.
- Re-resolving upstreams inside a retry loop.
- M01-T11 production deployment or Muse activation.
- Any unrelated D25 or Compose refactor.

## Acceptance

- Exact frozen resolution is reused for every retry attempt.
- Candidate build is attempted no more than three times.
- Retry happens only for the exact Ubuntu InRelease mismatch diagnostic.
- Generic build failures are attempted once and remain terminal.
- Three consecutive retryable mismatches end with existing `candidate_build_failed` pre-promotion evidence and no recreate/promotion.
- A retryable mismatch followed by a successful build enters the unchanged normal D25 validation/promotion path.
- Existing D25 tests remain GREEN.
- `bash scripts/validate-source.sh` is GREEN.
- No production runtime mutation occurs in this Card.
