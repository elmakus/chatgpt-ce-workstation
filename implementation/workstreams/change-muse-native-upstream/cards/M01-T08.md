### Must preserve

- The compatibility behavior belongs in `elmakus/codex-chatgpt-web`; Workstation MUST NOT gain request-body filtering/provider-routing logic.
- For a native Responses request with a validated model ID beginning `muse-`, remove only top-level tool entries with exact `type: "namespace"` and `name: "mcp__codex_apps__gmail"`.
- Preserve the relative order and content of every non-Gmail tool entry.
- When the exact Gmail namespace is absent, do not rewrite the request merely for this feature.
- Ordinary native/Codex-LB requests retain Gmail and all other tool entries unchanged.
- Browser-backed `chatgpt-web/*` behavior remains unchanged.
- Preserve existing native routing, Muse routing, catalog filtering, authentication isolation, bridge-artifact scrubbing and failure semantics.
- Existing compressed native request handling must remain correct. If this feature reserializes a decoded request body, stale transfer metadata such as `content-encoding` must not be forwarded; existing content-length regeneration/removal semantics must remain correct.
- No credential value may enter source, fixtures, logs or evidence.
- Production Muse remains unset during this Card; no CLIProxyAPI mutation or Workstation deployment is part of this Card.

### Must not / rationale that must travel

- Do not remove individual Gmail actions while leaving the namespace shape partially present; D30 accepts omission of the whole Gmail namespace.
- Do not strip any other namespace/tool without separate accepted authority.
- Do not transform the recursive Gmail schema in an attempt to preserve Muse Gmail semantics.
- Do not modify CLIProxyAPI/Meta provider configuration or source.
- Do not change Workstation Compose/runtime configuration.
- Do not broaden the fork into a generic provider-specific tool-filter framework without a current requirement.
