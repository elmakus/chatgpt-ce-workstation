## Evidence to establish

- Exact tool(s) and schema path(s) containing recursive `$ref` or equivalent recursive structure in the current Codex Desktop/app-server tool surface.
- Whether the recursion comes from built-in Codex tools, plugin-generated tools, MCP tools, or more than one category.
- Current OpenAI Codex schema generation/normalization behavior and any upstream issue/fix relevant to providers that reject recursive JSON Schema.
- Current `codex-chatgpt-web` normalization surface and whether a bounded Muse-only transformation can be implemented there without changing ordinary-native bytes.
- A safe transformation contract: how recursive references are expanded or truncated, what semantics are preserved/lost, and how cycles are bounded deterministically.
- Whether a narrower rule (specific known tools/schemas) is sufficient versus a generic cycle-breaking JSON-Schema sanitizer.
- Whether the required correction remains within accepted Project Definition but requires Strategic Planning revision, or requires Project Definition change.
- Regression set proving: Muse succeeds; ordinary native preserves original recursive schemas; Gmail and web-search prior rules remain intact; non-recursive properties/tools remain unchanged; malformed/unsupported schemas fail safely rather than being silently corrupted.
