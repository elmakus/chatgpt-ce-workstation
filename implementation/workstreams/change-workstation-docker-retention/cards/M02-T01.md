- This Card is read-only against the real Unraid Docker/BuildKit environment.
- Do not prune, delete, build, pull, recreate, restart, retag, or otherwise mutate Docker/BuildKit state.
- Determine the actual builder/backend/driver used by the workstation build path rather than assuming Buildx configuration equals Compose behavior.
- Determine whether cache attributable to this workstation can be scoped safely by builder isolation, cache metadata/filtering, or another backend-supported mechanism.
- Determine supported bounded GC controls such as age, size, or keep-storage semantics only from the installed backend/tooling.
- Preserve identity-driven cache reuse from R7-R8.
- Never select or recommend a global/unscoped prune path merely because a scoped mechanism is unavailable.
- Do not inspect unrelated private application data; collect only Docker/BuildKit/runtime facts required by M02.
- Do not expose secrets in durable evidence.

### Must not / rationale that must travel

- Do not run `docker system prune`, `docker image prune`, `docker builder prune`, `docker buildx prune`, or any equivalent mutation in this Card.
- Do not recreate the workstation container or invoke `scripts/update.sh` / a production build.
- Do not choose final retention thresholds or implementation commands before backend evidence proves their semantics and scope.
- If safe workstation-only cache attribution cannot be proven with the current builder arrangement, stop at evidence and route through workflow correction; do not weaken D28.

## Outcome

Produce durable, non-destructive target-backend evidence sufficient for Execution Prep to contract the concrete M02 cache-retention implementation without guessing the builder, driver, cache scope, or supported bounded-GC semantics.

## Scope

### Included

- Read current workstation build source needed to identify the intended build path.
- Read-only inspection of Docker Engine / Compose / Buildx versions and active context.
- Read-only inspection of available builders, their drivers/nodes, and the builder actually selected by the workstation build path.
- Read-only inspection of cache records/metadata and supported prune/GC options needed to determine workstation-only scoping.
- Determine whether a dedicated workstation builder/cache namespace is technically required to satisfy D28.
- Persist concise evidence and a bounded implementation recommendation for the next JIT Card.

### Excluded

- Any cache/image pruning or deletion.
- Any candidate build, update, pull, production recreation, container restart, or deployment.
- Implementing the M02 cleanup logic.
- Choosing arbitrary retention thresholds unsupported by target evidence.
- M03 multi-cycle orchestration and M04 live mutation.

## Acceptance

- Evidence identifies Docker Engine, Compose and Buildx/backend versions relevant to the target.
- Evidence identifies the active/default builder, driver and node/backend actually applicable to the workstation build path.
- Evidence establishes whether workstation cache records can be isolated safely with the current builder arrangement.
- Evidence records the exact supported bounded GC/prune controls and filters relevant to the selected scope.
- Evidence states whether a dedicated workstation builder/cache namespace is required.
- No Docker/BuildKit state mutation occurs.
- If safe scope cannot be proven, the result explicitly fails closed and names the workflow correction needed rather than proposing a global prune.
- The result is sufficient to create the concrete M02 implementation Card without another speculative backend assumption.

- Verify every executed Docker/BuildKit command is read-only.
- Cross-check selected backend facts against the workstation `compose.yaml` / build scripts.
