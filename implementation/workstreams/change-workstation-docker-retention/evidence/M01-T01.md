## Result

Implemented a post-success workstation image/tag retention phase in `scripts/update.sh`.

The retention phase:

- is invoked only after promoted-image identity, health and runtime verification are GREEN;
- verifies the exact current candidate ref and exact rollback ref still resolve to their expected immutable image IDs before any removal;
- inventories only the candidate repository and only `candidate-*` / `rollback-*` workstation lifecycle tags;
- protects exactly the current candidate ref and immediately previous rollback ref;
- removes older workstation lifecycle refs by ordinary `docker image rm <ref>` semantics, without force and without any global/system/image prune;
- safely un-tags stale duplicate refs that point to a protected image while the exact protected refs remain, preventing tag growth across repeated no-change builds;
- relies on normal Docker reference safety so another live tag/container reference prevents unsafe image-object deletion;
- records bounded retained/removed/failed reference evidence (maximum 64 refs per list, with total count and truncation marker);
- reports cleanup failure as a warning while leaving the verified production update status successful and never invoking rollback for cleanup failure.
