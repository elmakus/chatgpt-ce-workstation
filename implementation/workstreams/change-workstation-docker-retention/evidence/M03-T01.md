The harness proves:
- three consecutive successful updates with changing candidate/current/rollback identities;
- after each of the first three successful cycles, the Workstation lifecycle set is bounded to exactly the current candidate ref plus one immediate rollback ref;
- older candidate/rollback refs become removable only after the newer candidate has passed runtime verification;
- a subsequent runtime-failing candidate restores the exact immediately previous production image and runs zero image/cache retention cleanup;
- a later verified-success cycle with an injected stale-image removal failure remains production-successful and records `image_cleanup.status=warning`;
- a later verified-success cycle with an injected cache-GC failure remains production-successful and records `build_cache_cleanup.status=warning`;
- after the cleanup-warning recovery sequence, lifecycle refs return to exactly current + one rollback;
- a same-repository non-lifecycle ref and a foreign-repository candidate-like ref remain untouched;
- real updater `write_evidence` JSON is read back for success, rollback and cleanup-warning states;
- cache evidence records builder `chatgpt-ce-workstation`, driver contract `docker-container`, `max_used_space=24gb` and `reserved_space=8gb`;
- normal build source remains cache-enabled and explicitly selects the dedicated builder.
