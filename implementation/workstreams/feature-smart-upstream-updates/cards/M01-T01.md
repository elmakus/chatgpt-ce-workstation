### Must preserve

- Normal upstream policy is latest trusted stable/current while Ubuntu stays on the 24.04 LTS family.
- Resolve/freeze happens before candidate build execution; `ubuntu:24.04` must be bound to an exact digest or equivalent immutable identity before any candidate build consumes it.
- CE Git revision and official OpenAI ChatGPT Linux package identity are separate freshness inputs.
- CE remains the authority that consumes and validates the official OpenAI package through its signed stable repository path; workstation probing may inform freshness/cache keys but must not weaken or replace that trust chain.
- Resolution output is deterministic, inspectable and secret-free; normal mode contains no timestamp/random invalidation field.
- Explicit overrides remain visible in output and do not silently replace latest-stable defaults.
- Required upstream resolution fails closed rather than silently reusing stale state and claiming currentness.
- This Card must not recreate or otherwise mutate production.

### Must not / rationale that must travel

- Do not implement base-image handling by building from moving `ubuntu:24.04` first and recording the digest afterward; the immutable base identity must be frozen before build execution.
- Do not collapse CE source freshness and OpenAI package freshness into one value.
- If a required upstream cannot expose enough identity/trust evidence to meet approved authority, open a Research obligation rather than weakening the contract.

## Outcome

A canonical resolver framework exists with deterministic normalized output and independently frozen identities for the highest-risk trust boundaries: Ubuntu 24.04 base, CE selected Git revision and the signed OpenAI ChatGPT stable Linux package.

## Scope

### Included

- Define the canonical resolver output/manifest contract used by later updater/build integration.
- Implement pre-build Ubuntu 24.04 base digest/equivalent immutable resolution.
- Implement exact CE selected-branch Git commit resolution.
- Implement a separate OpenAI stable package freshness identity aligned with CE's signed repository metadata/validation path.
- Implement explicit override representation, provenance fields and fail-closed errors for these resolvers.
- Add fixture/unit tests for stable output, identity changes, malformed/unavailable metadata and overrides.
- Add source validation needed to prevent regression back to timestamp-only normal resolution semantics.

### Excluded

- Wiring the full resolver set into Docker/Compose candidate builds (M02).
- Production recreation/promotion/rollback (M03-M04).
- Final implementation choice for other component resolvers owned by M01-T02.

## Acceptance

- Same mocked/upstream state produces byte-stable normalized resolution content.
- Ubuntu base identity is exact and materialized before candidate build execution.
- CE commit and OpenAI package identity are distinct fields and can change independently in tests.
- OpenAI package probing preserves the CE signed-metadata trust boundary.
- Normal resolution contains no timestamp/random cache-busting value.
- Override use is explicit and provenance is inspectable without secrets.
- Required resolution failures are non-zero/fail-closed and cannot invoke production recreation.
- Existing source-validation/isolation/self-updater invariants remain intact.
