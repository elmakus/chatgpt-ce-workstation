### Must preserve

- `scripts/update.sh` is the single normal end-to-end updater; `scripts/build.sh` remains the lower-level exact/pre-resolved build primitive.
- Source validation -> host preflight -> image build must occur before production mutation.
- Resolver, validation, preflight, build and candidate-readback failure must leave the running production container untouched.
- Promotion must use the exact validated candidate image identity, not an ambiguous mutable `local` tag.
- Capture and retain the exact current production image identity immediately before mutation.
- Post-promotion health/runtime failure must attempt deterministic rollback, verify the restored exact prior image, and still report update failure.
- Rollback failure must be explicit and must never be reported as success.
- Compose remains the deployment authority; do not add Docker socket/privileged/runtime-self-updater shortcuts.
- M03 implementation/tests must not recreate or mutate the real production workstation. The explicit deployment/live-write gate remains M04.

## Dependencies

- `M02-T02`

## Outcome

The repository contains a fail-closed updater orchestration that can resolve/freeze/build one exact candidate, validate it, promote that exact image through Compose, verify live health/runtime, and restore the exact prior image when post-promotion verification fails.

## Scope

### Included

- Replace legacy timestamp-driven `scripts/update.sh` with resolver-driven orchestration.
- Carry one frozen resolution into the build and subsequent Compose commands.
- Add exact candidate provenance/readback before promotion.
- Capture/tag the exact previous image as rollback baseline.
- Add exact candidate promotion and running-image readback.
- Add deterministic rollback plus health/runtime/image-identity verification.
- Persist bounded secret-free update evidence.
- Add test seams/helper functions needed for isolated orchestration testing.

### Excluded

- Real production recreate/promotion/rollback.
- Native CE/Android Remote, Codex Web GPT routing, Agent Workspace/Computer Use live regressions; those remain M04.
- Changing accepted upstream channels, trust roots, isolation architecture or persistent-data layout.

## Acceptance

- Normal updater order preserves source validation -> host preflight -> exact candidate build before any production mutation.
- Candidate identity and embedded resolution are verified before promotion.
- Previous running image identity is retained before promotion.
- Exact candidate is the image actually recreated.
- Health/runtime failure invokes rollback; successful rollback is verified and returns update failure.
- Failed rollback is distinguishable and reports exact recovery identities/state.
- Bounded update evidence records resolution, candidate and previous-image identities without secrets.
- No legacy `UPSTREAM_REFRESH` behavior remains in `update.sh`.
- No real production mutation occurs while implementing/verifying this Card.

## Required tests / checks

- isolated updater orchestration tests covering success, pre-promotion failure/no mutation, post-promotion rollback success, and rollback failure;
- `bash scripts/validate-source.sh`;
- PR CI/source checks.
