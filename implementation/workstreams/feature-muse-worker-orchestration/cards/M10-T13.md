## Outcome

A new immutable `codex_workflow` candidate safely reconciles a durable `reserved` session record when the post-lock transition to `active` fails, without weakening the existing session/workspace race protections.

## Scope

### Included

- Bounded session-acquisition correction for failures while transitioning a created or resumed reservation to `active` after the session flock has been acquired.
- Durable rollback/reconciliation that does not leave an ownerless `reserved` record after the lease is released.
- Normalized adapter failure when durable reconciliation succeeds.
- Deterministic regression coverage for the exact activation-transition failure, including explicit replacement/retry availability.
- Full applicable runtime/adapter/profile/package regression verification.

### Excluded

- Project Workflow policy/state changes.
- New public session-recovery API or strategic lifecycle redesign.
- Companion semantics.
- Release/version bump, publication, merge to `codex_workflow:main`, or production promotion.
- Live Meta-backed revalidation, which is M10-T14.

## Acceptance

- Failure of the post-lock `reserved -> active` persistence step does not leave an ownerless `reserved` record.
- A newly-created reservation is removed safely on activation failure when rollback is durable.
- A resumed reservation is restored safely to its prior `ready|needs_probe` state on activation failure when rollback is durable.
- The failure is returned as a normalized `adapter_internal` result when durable reconciliation succeeds.
- Explicit replacement remains possible after a failed new-worker acquisition; safe exact-session retry remains possible after a failed resumed acquisition.
- Existing reservation/locking/quarantine/binding/replacement/concurrency regressions remain GREEN.
- Runtime suite, Muse adapter suite, profile suite, compile/package validation/build/archive verification and `git diff --check` are GREEN.
