Make `muse-max` a correctly represented mixed-harness profile and make the existing Muse runner profile-aware enough that it cannot bypass active profile/role allocation.

- The Muse runner also rejects any requested role when the active profile does not assign it to `muse-code`.
- Model/reasoning/harness values come from profile authority rather than runner constants.
- `CODEX_HOME` is honored consistently with the rest of `codex_workflow`.
- Existing role TOMLs remain the only role-semantic definitions.
- No contradictory “all seven Muse” / one-shot Companion statements remain in active docs.
- Regression tests prove `plus`, `luna-xhigh`, and `pro-x5` retain existing allocations/lifecycle semantics.
