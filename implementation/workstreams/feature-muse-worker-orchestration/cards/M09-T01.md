## Outcome

Produce the exact reviewable M09 source candidate that lets Main/codex_workflow concurrently await already-authorized independent Muse lane invocations without adding a second project scheduler, while preserving per-lane process ownership, isolation, normalized-result semantics and all non-`muse-max` profile behavior.

## Included scope

- Add the smallest managed concurrency surface over the existing single-run Muse adapter.
- Accept only explicit caller-supplied lane invocations; do not discover dependencies or create project lanes/worktrees.
- Validate that concurrently submitted workspaces are distinct and non-overlapping.
- Keep executor -> tester -> optional repair -> fresh tester ordered inside each lane; concurrency applies only across already-independent lanes.
- Protect active Muse run artifact directories from retention cleanup while concurrent invocations are still running.
- Preserve per-invocation timeout/cancel/process-tree ownership so one lane failure/cancel does not silently cancel another lane.
- Preserve one normalized result and private raw artifact set per invocation, with no shared-log collision.
- Add deterministic concurrency/failure-isolation regression coverage.
- Add the Muse adapter suite to repository CI so the final source candidate is covered on PR.
- Reconcile release/runtime documentation that still describes the superseded all-Muse/sequential/sandbox behavior, without version bump or publication.

## Excluded scope

- Project Workflow scheduling, Task Board ownership, dependency resolution, `parallel_safe` classification, branch/worktree creation or a second task database.
- Concurrency inside one lane's executor/tester/repair sequence.
- Changes to `plus`, `luna-xhigh` or `pro-x5` allocations/lifecycle.
- Changes to the accepted Companion model/lifecycle.
- Live internal Companion creation/reuse.
- Release version bump, merge to `main`, GitHub Release publication or workstation production update.
- Workstation rebuild/recreate/login/auth changes.

## Acceptance

- Two caller-authorized non-overlapping Muse invocations can be concurrently awaited through one managed runtime surface.
- Overlapping/equal workspaces are rejected before either lane is started.
- Each lane retains a distinct run ID/artifact directory and bounded normalized result.
- Active run directories are protected from retention deletion while another concurrent lane finishes/retention-runs.
- A controlled failure or cancellation in one lane does not cancel/corrupt a healthy lane.
- No unmanaged background shell orchestration is introduced.
- Existing profile allocation/lifecycle regressions for `plus`, `luna-xhigh`, `pro-x5` and mixed `muse-max` stay GREEN.
- Existing Muse adapter protocol/failure/cancellation/retention tests remain GREEN and new concurrency tests are GREEN.
- Repository validation/build/package verification remain GREEN.
- Release/runtime documentation matches the accepted mixed-harness and current Docker sandbox behavior.
- The exact final source subject is frozen for independent review; no publication/promotion occurs in this Card.
