### Must preserve

- Keep the existing Xvfb -> Openbox -> Tint2 -> x11vnc -> noVNC desktop architecture.
- Keep the Tint2 recovery panel visible at the bottom, full screen width, 38 px high, above normal windows.
- Keep the panel as an EWMH dock with a 38 px bottom strut so maximized windows do not cover it.
- Preserve all current launchers/taskbar/systray behavior.
- Do not weaken the container isolation boundary or modify noVNC/VNC exposure.

### Must not / rationale that must travel

- Do not work around the defect by hard-coding a half-screen Openbox margin.
- Do not modify application-specific Chrome geometry; the defect is desktop workarea calculation and affects every maximized window.
- Do not deploy/rebuild the production workstation or merge to `main` in this Card.

## Dependencies

- none

## Outcome

The noVNC desktop reports a correct full-width workarea and Openbox maximizes application windows across the usable screen width while preserving the bottom Tint2 panel reservation.

## Acceptance

- On 1280x720 and 1920x1080 Xvfb displays, `_NET_WORKAREA` is `0,0,width,height-38` on every Openbox desktop.
- Tint2 remains `_NET_WM_WINDOW_TYPE_DOCK`, spans the full display width, sits at `y=height-38`, and publishes a 38 px bottom strut.
- A maximized X11 test window starts at x=0 and has client width equal to the full display width rather than half the display.
- The old `panel_dock = 1` configuration is demonstrably caught by the regression probe.
- Existing source validation, ShellCheck, Dockerfile static checks and secret scan remain GREEN.
