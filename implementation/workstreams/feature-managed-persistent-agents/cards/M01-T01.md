### Must preserve

- `~/.codex/AGENTS.md` remains under the persistent `/home/codex` home and the workstation must not take ownership of the whole file.
- The repository/image owns exactly one explicitly delimited workstation block; reconciliation updates only that block.
- Content outside the workstation block must be preserved, including the independent `codex-workflow-user-managed-start` / `codex-workflow-user-managed-end` block and arbitrary user text.
- Fresh seed, later managed updates and the one-time known legacy migration must use one coherent reconciliation lifecycle.
- Legacy migration may replace only an exactly recognized repository-owned legacy workstation prefix; ambiguous unmarked legacy input must remain byte-identical and produce a clear diagnostic.
- Duplicate/unmatched/malformed workstation markers must fail closed without destructive repair.
- Reconciliation must be content-idempotent.
- Existing ownership/mode expectations and the Docker isolation boundary must remain intact; do not add Docker socket, host-root access, extra privileges, or host-control surfaces.
- The existing narrow `/workspace` stock-text migration may be removed/subsumed only when the new lifecycle covers its accepted purpose without broadening ownership.
- Production persistent `~/.codex/AGENTS.md` is not an M01 write target. M01 may use repository fixtures and isolated temporary paths only.

### Must not / rationale that must travel

- Do not use heuristic whole-file ownership, fuzzy matching, broad text rewriting, or implicit manual overwrite fallback.
- Do not modify the independently owned `codex_workflow` block.
- Do not deploy/recreate the workstation or perform another live write to the production persistent AGENTS file in this Card.
- Do not freeze marker spelling, helper language or optional metadata beyond what safe implementation/testing requires.

## Outcome

Repository source safely seeds, reconciles and conservatively migrates the workstation-owned global AGENTS policy, with deterministic isolated verification and no production persistent-file mutation.

## Scope

### Included

- Add one repository-owned reconciliation helper with an explicit target-path test seam.
- Represent the workstation-managed payload from repository/image source.
- Integrate reconciliation into the existing `INSTALL_GLOBAL_AGENTS` initialization path.
- Encode conservative recognition of the known repository-owned legacy workstation prefix/layout.
- Preserve ownership/mode expectations on create/update/migration.
- Retire or subsume the old narrow `/workspace` migration when equivalently covered.
- Add fixture-based tests for every R11 case, including exact preservation and idempotency.
- Extend source validation so the managed lifecycle/safety boundary cannot silently disappear.
- Extend runtime verification so an authorized later deployment can assert the current managed workstation policy without dumping unrelated persistent content.

### Excluded

- Any write to the currently running workstation's persistent `~/.codex/AGENTS.md`.
- Workstation rebuild/recreate, live migration, rollback execution or live idempotency proof (M02).
- Changes to `codex_workflow`-owned content.
- New generic multi-manager configuration framework.
- New privileges, Docker socket, host-root mounts or host-side control mechanisms.

## Acceptance

- Fresh missing target produces exactly one valid workstation-managed block carrying the current image-owned policy.
- Existing valid managed target replaces only the workstation block and preserves every byte outside it.
- The known live legacy shape migrates by replacing only the exactly recognized repository-owned legacy prefix while preserving the existing `codex_workflow` block exactly.
- Arbitrary unrelated text before/after/between owned regions survives unchanged.
- Ambiguous legacy and malformed/duplicate marker fixtures are byte-identical after reconciliation and emit a clear failure diagnostic.
- Reconciliation is byte-identical on a second run against current output.
- Ownership/mode handling remains compatible with the persistent-home model.
- Source validation includes the managed reconciliation contract and remains GREEN.
- Runtime verification can confirm one current managed block after later authorized deployment without exposing unrelated file content.
- M01 performs no production persistent-file mutation.
