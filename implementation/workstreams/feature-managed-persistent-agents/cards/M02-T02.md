## Hard authorization gate

Before this Card may become `ready` or perform any action that can rewrite the running workstation's persistent `~/.codex/AGENTS.md`, obtain explicit current user authorization for the production deployment/live write.

Feature approval, plan approval, M01 review, M02-T01 review or a prior unrelated deployment authorization do not satisfy this gate.

## Must preserve

- Deploy only the exact candidate image/source proven by M02-T01; verify the candidate image ID immediately before recreate.
- Preserve a practical rollback copy/path for the current persistent AGENTS file before first migration.
- Preserve the independently owned `codex_workflow` suffix and unrelated content exactly.
- Let container initialization perform migration; do not hand-edit the production AGENTS file as a shortcut.
- If reconciliation reports ambiguity/malformed state, stop and preserve evidence; do not overwrite manually.
- Keep the existing Docker isolation boundary and tracked Compose deployment path.
- Retain rollback evidence until live acceptance is GREEN.

## Outcome

The production workstation is recreated on the exact reviewed candidate, the legacy persistent AGENTS file migrates through the workstation-owned reconciler, runtime verification proves the current managed policy and preserved foreign content, and a second reconciliation/recreate proves live idempotency.

## Included

After explicit user authorization:

- Re-read the bounded live baseline and verify it still matches the M02-T01 reviewed deployment capsule.
- Create a timestamped rollback copy of the persistent AGENTS file with metadata/hash recorded.
- Verify the candidate image ID still equals the reviewed M02-T01 candidate.
- Recreate the workstation through tracked Compose using the prepared image.
- Wait for healthy and run `scripts/verify-runtime.sh`.
- Verify exactly one workstation-managed block matches the deployed image payload without dumping unrelated content.
- Verify the `codex_workflow` suffix and unrelated preserved remainder against pre-deployment evidence.
- Verify mode/ownership expectations.
- Perform one further safe reconciliation/recreate cycle as needed to prove live idempotency and re-run health/runtime verification.
- Preserve rollback artifact until all acceptance checks are GREEN.

## Excluded

- No manual whole-file overwrite or heuristic repair.
- No changes to `codex_workflow`-owned content.
- No unrelated upstream refresh/update.
- No new privileges, Docker socket, host-root or host-control surfaces.

## Acceptance

- Production target has exactly one valid workstation-managed block matching the prepared image payload.
- Existing `codex_workflow` managed content is byte-identical to the reviewed pre-deployment baseline.
- Unrelated persistent content is preserved.
- Integrated X11/ydotool workstation guidance is present via the managed block.
- Runtime health and `scripts/verify-runtime.sh` are GREEN.
- A second reconciliation/recreate is content-idempotent.
- Rollback copy/hash/path is recorded and retained through acceptance.
- The production deployment uses the exact M02-T01 reviewed candidate image.

## Required checks

- Pre-write bounded baseline revalidation.
- Candidate image-ID readback.
- Rollback-copy hash/stat readback.
- `bash scripts/run.sh --recreate`.
- `bash scripts/wait-healthy.sh`.
- `bash scripts/verify-runtime.sh`.
- Bounded managed-block/current-payload check.
- Pre/post `codex_workflow` suffix hash comparison.
- Full target SHA comparison across the idempotency cycle.

## External write/readback

This Card performs the explicitly authorized production persistent-file/container write. Use WRITE → READBACK → VERIFY → EVIDENCE for every material step.

## Independent review

`none` — the high-risk pre-write readiness package is independently reviewed in M02-T01; this Card is constrained to executing that reviewed capsule after explicit user authorization, with mandatory post-write readback. Any material candidate/procedure drift routes back to preparation/review rather than being silently accepted.
