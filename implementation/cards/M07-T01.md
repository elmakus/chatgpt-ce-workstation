### Must preserve

- `muse-max` remains the only profile changed by Muse routing; `plus`, `luna-xhigh`, and `pro-x5` preserve existing allocation/lifecycle behavior.
- Companion remains an internal persistent GPT-5.6 Luna XHigh worker and must be rejected by the Muse adapter.
- The six existing Muse-backed role TOMLs remain the canonical semantic role contracts; no duplicate Muse role definitions.
- One assignment maps to one bounded leaf `muse exec` process. No nested-worker orchestration, sibling messaging, Project Workflow state mutation, or project-level branch/worktree ownership is added.
- Active profile/role/model/reasoning/harness authority comes from `compute_profiles.py` and shared runtime paths, including `CODEX_HOME`.
- Bind argv/protocol behavior only to M05-observed Muse Code 1.3.0 evidence: JSONL stdout, diagnostic stderr, explicit model/max effort, terminal completed/failed records, output-schema support, headless input auto-resolve, and current workstation sandbox limitation.
- Raw JSONL/stderr stay outside project Git/Main context under persistent user runtime data with bounded retention; normal output is one compact normalized result.
- Timeout/cancel must drain output and terminate the full observed process subtree with bounded graceful-then-hard cleanup.
- Missing/malformed terminal protocol, malformed normalized report, provider/model failure, auth/runtime failure, timeout, cancellation and adapter/internal failure fail closed.
- Normalized results must not intentionally expose credentials/session secrets or raw trajectories.

- Do not add concurrency; M09 owns lane concurrency after M07/M08 establish the single-run adapter/orchestration shape.

## Outcome

`codex_workflow` has a production-oriented single-invocation Muse adapter that builds M05-supported argv from active profile authority, continuously drains/persists raw process output, validates terminal JSONL plus a versioned final worker report, emits one bounded normalized result, enforces retention, and handles timeout/cancel/process-tree cleanup deterministically.

## Scope

### Included

- Versioned normalized result/report contract for common fields and tester verdict.
- Muse-only final structured-output overlay without changing shared role semantics.
- Profile-aware command construction and assigned workspace/cwd.
- JSONL terminal parsing and report validation.
- Continuous stdout/stderr draining to per-run artifacts under `CODEX_HOME`.
- Run identity/artifact references and bounded retention by count/age/size.
- Bounded normalized Main-facing JSON, including optional changed-path/diff-stat evidence.
- Timeout and cancellation with process-tree cleanup.
- Failure classification required by R14.
- Secret-safe normalized-output handling.
- Deterministic fixture/fake-process tests covering success, protocol/report failures, profile rejection, timeout/cancel/tree cleanup and retention.
- General regression protection for non-Muse profiles.

### Excluded

- Live Muse invocation on the workstation.
- M08 role-orchestration/RED-repair pilot.
- M09 concurrency/release/promotion.
- Workstation image/source changes unless a later live finding proves one necessary.

## Acceptance

- A valid fake Muse run yields exactly one normalized result with schema version, task ID, role, completed status, bounded summary/findings/checks/limitations, artifact references and tester verdict semantics where applicable.
- Raw JSONL and stderr are persisted to per-run runtime artifacts and are not copied into the normal normalized result.
- The adapter accepts only the active role's `muse-code` allocation and uses its model/reasoning values.
- Missing/duplicate/malformed terminal records and invalid/missing final structured report fail closed.
- Provider/model and auth/runtime failures are distinct from protocol/report/internal failures.
- Timeout and explicit cancellation leave no surviving fake Muse child subtree after cleanup.
- Retention is demonstrably bounded by configured count/age/size behavior.
- `plus`, `luna-xhigh`, and `pro-x5` regressions remain GREEN.
